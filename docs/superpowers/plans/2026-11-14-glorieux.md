# Glorieux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Déployer la billetterie Glorieux sur AWS avec HTTPS et son dépôt GitHub.
**Architecture:** Django, Bootstrap, SQLite dédiée, tâches de distribution persistantes. Service systemd plafonné à 192 Mo, un worker, port local 8017 et vhost Apache ajouté sans modifier les autres services.
**Tech Stack:** Python 3.12, Django 5.2 LTS, Gunicorn, WhiteNoise, boto3, QRCode, Pillow, ReportLab.
**Spec:** `CAHIER_DES_CHARGES.md`.

## Global Constraints

- Double vérification email grandlebrun.com et SMS avant réservation.
- Aucune simulation de paiement ou validation de téléphone en production.
- Un billet par participant et téléphone par événement ; scan public sans consommation.
- Rôles superadmin, administrateur, organisateur, valideur et étudiant ; autorisation serveur.
- Secrets hors Git et hors interface ; services existants préservés.

## Review Focus

- Paiement tardif : réserver les places des paiements en attente jusqu’à réconciliation.
- Mineur : déclaration personnelle par bénéficiaire, jamais par acheteur tiers.
- Double scan : mise à jour conditionnelle atomique.
- SMS/email en panne : tâches persistées et reprises, code jamais exposé.
- Appareil révoqué : autorisation revérifiée à chaque scan.
